# 貢獻者 PR 工作流程

這個技能引導貢獻者從零開始，完整跑完新增或修改知識庫內容的流程，最後開出 Pull Request。

## 使用情境

- 你想新增一個建築相關的知識技能到這個知識庫
- 你想修改或補充現有的技能內容
- 你想重新命名或重組目錄結構
- 你不確定流程對不對，想要一個檢查清單跑一遍

## 學習目標

完成這個流程後，你應該能夠：

1. 理解知識庫的三層目錄結構與命名規則
2. 從樣板建立新的技能
3. 正確填寫 SKILL.md 的 frontmatter
4. 為技能補上父層 index.md 的連結
5. 在送出 PR 前自我驗證所有常見錯誤
6. 使用 Conventional Commit 格式送出 PR

## 實務應用

這個技能適合：

- **第一次貢獻者**：照著步驟做，不用擔心漏掉什麼
- **開 PR 前的最後檢查**：跑一遍 Phase 5 的自我驗證，確保不會被 reviewer 退件
- **課堂或工作坊教學**：帶學生或團隊練習開 PR 時的標準教材

## 常見錯誤

| 錯誤 | 後果 | 怎麼避 |
|------|------|--------|
| `skill.md` 小寫 | AI 無法識別 | 確保大寫 `SKILL.md` |
| `name` 不等於目錄名 | Frontmatter 驗證失敗 | copy 時就改好 |
| domain.md 有 frontmatter | 顯示異常 | domain.md 不加 `---` |
| 簡體中文 | 違反專案語言規則 | 送出前 grep 檢查 |
| 髒檔案進 PR | reviewer 退回 | 檢查 `.history/` `.vscode/` |
| index.md 沒更新 | 技能沒出現在目錄 | Phase 5 check |
